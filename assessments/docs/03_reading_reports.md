# 03 · 学习评估报告解读

考核不只是「绿了/红了」：每次运行都会把结果写进**账本**，报告生成器据此产出一份
**学习评估报告**——告诉你总分、每个模块的得分、四类知识点的掌握率、哪些知识点需要加强、
以及和上一次相比进步了多少。

---

## 一、报告怎么生成

```bash
# 1) 先跑考核（把结果写进账本）
cargo test --no-fail-fast                  # 全部 18 课；只考一课用 --test lesson_XX_主题

# 2) 再生成报告
cargo run --bin assessment_report

# 其它常用参数
cargo run --bin assessment_report -- --list         # 列出账本里的历史运行
cargo run --bin assessment_report -- --run <运行ID>  # 分析指定的一次运行
cargo run --bin assessment_report -- --emit-map     # 重新生成知识点覆盖矩阵
cargo run --bin assessment_report -- --check-map    # 校验矩阵与考核代码是否一致
```

Windows 一键脚本（自动完成上面两步）：`.\assessments\scripts\run_assessments.ps1`

产物：

| 文件 | 用途 |
| --- | --- |
| `assessments/report/assessment_report.md` | **人读的学习评估报告**（本节讲的就是它） |
| `assessments/report/summary.json` | 机器可读摘要（成绩趋势、各模块得分） |
| `assessments/report/data/history.jsonl` | 每次运行一行，用于「学习进度对比」 |
| `assessments/report/data/ledger.tsv` | 账本：每个知识点的 start / ok / fail / missing / panic / pass 事件 |
| `assessments/report/data/last_run.log` | 最近一次 `cargo test` 的完整输出（脚本会写） |

> `report/data/` 是你的**个人进度数据**（已加入 `.gitignore`）：想清零进度就删掉整个目录，
> 不影响考核本身。样例报告放在 `assessments/report/samples/` 里，可以直接对比着看。

---

## 二、报告的结构与读法

### 2.1 总览

```
总分：72 / 100（合格）   通过 34 · 未实现 12 · 未通过 4 · 运行期错误 1
一句话诊断：语法基础已经扎实，但「所有权/借用」「并发」两类知识点还没过关。
```

- **总分** = 通过的知识点数 ÷ 应掌握的知识点总数 × 100（四舍五入）；
- **等级**：≥90 优秀 / ≥75 良好 / ≥60 合格 / <60 待加强；
- 四个计数是互斥的状态，加起来等于应掌握的知识点总数。

### 2.2 模块得分表（按课程顺序）

| 模块 | 知识点数 | 通过 | 未实现 | 未通过 | 得分 | 等级 |
| --- | --- | --- | --- | --- | --- | --- |
| lesson_03 函数 | 8 | 8 | 0 | 0 | 100 | 优秀 |
| lesson_05 所有权系统 | 9 | 6 | 2 | 1 | 67 | 合格 |

**看两件事**：得分最低的几行（薄弱模块）、「未通过」不为 0 的行（这类是**真的做错了**，
比「未实现」更需要立刻处理）。

### 2.3 四类知识点掌握率

```
基础 92%（23/25）   核心 74%（20/27）   难点 45%（5/11）   边界 60%（6/10）
```

这一节专门看**难点**与**边界**：它们最能反映「是看懂了还是掌握了」。
如果「基础」很高但「难点/边界」很低，通常说明只跟着课程跑了一遍示例，没自己动手推导。

### 2.4 逐条明细（最重要的部分）

每条长这样：

```
- [未通过·难点] kp_05_04 可变引用的唯一性（NLL）
  位置：assessments/lesson_05_ownership_borrowing.rs:349
  原因：值不相等（期望 6，实际 3）
  提示：两次 &mut 借用不能重叠：push 完再用 len()，或重新获取借用
  复习：复习 lesson_05 示例 6（mutable_borrow）……
  复习入口：cargo run --bin lesson_05_ownership_borrowing（src/tutorial/lesson_05_ownership_borrowing.rs）
```

字段含义：

| 字段 | 怎么用 |
| --- | --- |
| 状态 `[未通过·难点]` | `通过` / `未实现` / `未通过` / `运行期错误` + 知识点分类 |
| `kp_05_04` + 标题 | 知识点编号与主题 |
| 位置 | **直接跳过去改这一行**（`文件:行号`） |
| 原因 | 期望值 vs 实际值（或 panic 信息） |
| 提示 | 这一类知识点该检查什么（考核作者写的） |
| 改进建议 | 按知识点分类给出的通用改进方向（基础/核心/难点/边界各不同） |
| 复习 / 复习入口 | 回到哪一课、跑哪条命令、看哪个示例 |

### 2.5 需要加强的领域 + 下一步行动清单

报告结尾会把「未通过 + 未实现」最多的模块排出来，并给出**具体可执行**的建议
（例如「先重跑 lesson_05 示例 5~7，再用注释写出借用关系图」），最后给 3~5 条行动清单。
建议一次只处理 1~2 个知识点，改一处就跑一次测试。

### 2.6 学习进度对比

```
与上一次运行（2026-02-03 21:14）相比：
  总分 61 → 72（+11）
  本次新通过：kp_05_01, kp_05_03, kp_08_07 …（共 8 个）
  本次退步：kp_06_03（之前通过，本次未通过）
```

- 「新通过」= 上次不是通过、本次通过的知识点；
- 「退步」= 上次通过、本次没通过的知识点——通常意味着改动别处时**碰坏了**这段代码，
  报告会把它列出来提醒你回头检查；
- 首次运行会说明「这是首次记录，暂无可对比的历史」。

## 三、评分口径与几个边界情况

1. **应掌握的知识点总数**取「账本里出现过的全部知识点」（即 18 课考核文件里登记的知识点总数）。
2. **某课编译不过怎么办？** 如果 `assessments/lesson_XX_*.rs` 里的实现有语法/类型错误，
   该测试目标根本跑不起来，账本里就没有它的记录。报告会把它单列为
   **「未运行或编译失败」**，并提示你先按编译器报错修好——这类不计入「通过」。
3. **重复运行同一次考核？** 同一个运行 ID 下重复跑同一个测试目标时，报告对每个知识点
   **只取最后一组结果**，所以先失败后通过不会重复计数。
4. **运行 ID 是怎么定的？** 脚本会设置 `ASSESSMENT_RUN_ID`（形如 `run-20260204-101530`）；
   如果你是直接敲 `cargo test`，框架会把 10 分钟内连续运行的 18 个测试目标归并成同一次考核。
5. **只想看某一课的报告？** 用 `cargo test --test lesson_05_ownership_borrowing` 只跑这一课，
   报告仍会列出全部知识点的状态：没跑过的课会显示为「未运行」，不会拉低你的总分口径
   （总分始终按全部知识点计算，便于横向比较）。
6. **报告生成器的退出码**：全部通过 → 0；否则 → 1。方便脚本/CI 判断（例如把它接进自己的打卡流程）。
7. **报告里的时间**：自动化脚本会把本机时区偏移传给报告生成器（环境变量 `ASSESSMENT_LOCAL_OFFSET_MINUTES`），
   因此报告显示的是**本地时间**；如果你自己直接运行 `cargo run --bin assessment_report` 而没经过脚本，
   报告会明确标注时间为 **UTC**（不会把 UTC 冒充成本地时间）。

## 四、把报告变成学习闭环

推荐每学完一课就走一遍这个循环（10~30 分钟）：

```
读课 + 跑课程示例  →  cargo test --test lesson_XX_主题  →  实现 exercise_*  →  变绿
        ↑                                                                      ↓
        └────────────  读报告「复习 / 提示」字段，回到对应示例  ←──────────────┘
```

每周末再看一次总报告：

- 「难点」「边界」两类的掌握率是否在上升？
- 有没有出现「退步」的知识点（说明改动时碰坏了旧代码）？
- `--list` 里的历史运行是否在稳步减少「未实现」的数量？

> 报告里的**复习入口**（课程文件 + 运行命令 + README 条目）是刻意给的：
> 考核失败时不要硬猜，按指引回到课程对应示例，把「为什么这样写」讲清楚，再回来改。
