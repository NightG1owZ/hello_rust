# 学习方法论：如何高效使用本项目学 Rust

> 本文档沉淀「怎么学」：三份材料如何配合、编译错误怎么读、每课做到什么程度算学会。
> 「学什么」见 [根 README](../../../README.md) 与 [教程目录 README](../README.md)。

---

## 一、三份材料的定位与配合

```
src/tutorial（01~13 学语言，14~18 补关键缺口，guides 讲方法）──► src/demoweb（真实 Web 服务，综合运用）
```

| 材料 | 回答的问题 | 正确用法 |
| --- | --- | --- |
| `src/tutorial/lesson_01~13` | 这个语言特性「是什么、怎么写」 | 按顺序学，每课独立可运行，跑一遍再读注释 |
| `src/tutorial/lesson_14~18` | 关键进阶特性（闭包/迭代器/智能指针/并发/宏）「怎么写」 | 学完 01~10 后插入学习 |
| `src/tutorial/guides` | 「为什么这样设计」「怎么学得快」「工具怎么用」 | 遇到瓶颈时查阅，不必通读 |
| `src/demoweb` | 这些知识「在真实项目里长什么样」 | 课程学完后通读源码，对照踩坑记录 |

**常见错误用法**：跳过 lessons 直接啃 demoweb；只读代码不动手跑；把 guides 当小说通读（它是工具书，不是教材）。

## 二、每课的标准学习循环（四步法）

1. **猜**：运行 `cargo run --bin lesson_XX_主题` 之前，把每个示例的输出写在纸上；
2. **对**：运行程序，逐行核对 `// 预期输出：` 断言（每一条都可用 [.dsh/check_expected_output.ps1](../../../.dsh/check_expected_output.ps1) 自动核对）；
3. **破**：把文件里注释掉的「错误示例」取消注释，亲眼看到编译错误/panic，再恢复注释；
4. **改**：改一个类型、删一个 `mut`、换一个分支，猜编译器会说什么，再验证。

> 判断标准：能向一个没学过的人讲清楚「示例 N 为什么输出这个」（费曼技巧）。讲不清楚，就回第 3 步。

## 三、编译错误阅读法（三步）

Rust 编译器报错的信息量远超大多数语言，读错信息的顺序应该是：

| 步骤 | 做什么 | 以 `error[E0382]: borrow of moved value: \`s\`` 为例 |
| --- | --- | --- |
| 1. 读主错误 | `E0382` 是编号，描述说清了「发生了什么」 | 值 `s` 已经被移动（moved），不能再借用 |
| 2. 看 help/ note | 编译器会标注**两个位置**：移动发生在哪、非法使用发生在哪 | `move occurs because \`s\` has type \`String\`...` |
| 3. 想所有权 | 问自己：这是 move？借用冲突？还是生命周期问题？ | String 是非 Copy 类型，赋值/传参即 move |

### 本项目高频错误编号速查

| 编号 | 含义 | 详见课程 |
| --- | --- | --- |
| E0382 | 使用已被移动的值 | lesson_05、lesson_14 示例 10 |
| E0502 | 可变借用与不可变借用冲突 | lesson_05、lesson_15 示例 10 |
| E0596 | 给不可变数据加可变借用（缺 `mut`） | lesson_16 示例 9 |
| E0597 | 借用超过了被借数据的存活期 | lesson_13、lesson_14 示例 10 |
| E0277 | trait bound 不满足（含 `Send`/`Sync`） | lesson_11、lesson_17 示例 7 |
| E0282 | 类型标注缺失（常见于 collect） | lesson_15 示例 10、lesson_18 |
| E0072 | 递归类型无限大小（需 Box） | lesson_16 示例 1 |
| E0308 | 类型不匹配（含闭包推断锁定） | lesson_14 示例 10 |

**心法**：编译错误不是「程序写错了」的惩罚，而是编译器在替你排除一整类运行期 bug。把每次报错当免费代码评审。

## 四、三条学习路线

### 路线 A：零基础（约 5~6 周）

```
第 1 周   lessons 01 → 04            语法基础
第 2 周   lessons 05 → 07            所有权 / 结构体 / 枚举（分水岭，放慢速度）
第 3 周   lessons 08 → 10            集合 / 模块 / 错误处理
第 4 周   lessons 11 → 13            泛型 / Trait / 生命周期
第 5 周   study practice 14 → 18     闭包 / 迭代器 / 智能指针 / 线程 / 宏
第 6 周   demoweb 通读 + 动手扩展一个接口
```

### 路线 B：有其它语言经验（约 2~3 周）

先读 guides/[02_language_theory.md](02_language_theory.md) 建立「所有权心智模型」，再按 `05 → 07 → 10 → 12 → 14 → 15 → 16 → 17` 的顺序精学，其余课程快读补漏。

### 路线 C：目标 Web 后端

lessons 05/07/10/12 → study 14（闭包）/15（迭代器）/16（智能指针）→ 17（并发）→ demoweb 按其 README 的阅读顺序（config → error → state → service → controller → 中间件 → 测试）。

## 五、自检清单（学完一课的标准）

- [ ] 能不看注释说出每个 demo 的输出；
- [ ] 能解释该课至少 3 个「预期输出」背后的原理（不是背答案）；
- [ ] 至少亲手制造过 2 个编译错误并说清成因；
- [ ] 改动过的代码用 `cargo clippy --bins` 检查无新警告；
- [ ] 能说出这一课知识在 demoweb 里的落点（每门课头部注释都标了对应位置）。

## 六、常见误区

| 误区 | 纠正 |
| --- | --- |
| 「先背语法再写代码」 | 所有权是**心智模型**不是语法：画内存图（谁拥有、谁借用、活到什么时候）比背规则有效 |
| 「编译器烦人，总不让我写」 | 每条拒绝都对应一类线上事故；把编译器当结对评审 |
| 「`clone()` 一下就过了」 | 滥用 clone 会掩盖所有权设计问题；先想「到底谁该拥有」，再考虑 clone |
| 「工具越多越好」 | stable + rust-analyzer + clippy 足够支撑本项目全部课程（见 [04_toolchain_guide.md](04_toolchain_guide.md)） |
| 「理论文档要一次读完」 | guides 是按需查阅的手册：卡住了再来查对应小节 |
| 「demoweb 代码看不懂是我没天赋」 | demoweb 是综合运用；看不懂说明前面的课有缺口，回到对应课程而不是自我怀疑 |
